# Rigol Agent 功能范围与后续计划确认

## 1. 当前阶段计划

当前阶段只计划完成示波器“测量功能”的点击配置和基础演示。

用户通过自然语言描述测量任务，例如：

```text
测量 CH2 的最大值
测量 CH4 的峰峰值
测量 CH1 的周期
测量 CH3 的频率
```

Agent 将指令转换为可执行步骤，例如：

```text
选择通道
→ 打开 Measure
→ 选择 Vertical 或 Horizontal
→ 点击测量项目
→ 关闭 Measure 窗口
```

第一版计划支持：

### 通道

```text
CH1
CH2
CH3
CH4
```

### 测量面板

```text
Vertical
Horizontal
Other（第一版只支持切换面板）
```

### 测量项目

```text
Maximum
Minimum
Peak-to-Peak
Period
Frequency
```

当前阶段的目标是验证：

```text
自然语言
→ 测量步骤规划
→ 组件与 ID 映射
→ 生成任务 JSON
→ 视觉定位
→ 机械臂点击
→ 点击后状态确认
```

当前阶段不要求 Agent 读取最终测量数值，也不要求覆盖示波器的全部操作。

## 2. 测量点击配置完成后的候选工作

以下内容是当前测量点击 Demo 完成后可以继续发展的方向，需要和导师确认哪些属于本项目最终范围。

### 2.1 扩充测量项目

在第一版五种测量项目基础上，继续支持：

#### Vertical

```text
Top
Base
Amplitude
High
Middle
Low
Average
RMS
Overshoot
Preshoot
Area
Period Area
```

#### Horizontal

```text
Positive Width
Negative Width
Rise Time
Fall Time
Positive Duty
Negative Duty
Positive Pulses
Negative Pulses
Positive Edges
Negative Edges
```

#### Other

```text
不同边沿组合的 Delay
不同边沿组合的 Phase
```

这部分主要是继续增加视觉类别、Agent 参数和任务模板，仍属于“测量菜单点击配置”。

### 2.2 读取和返回测量结果

点击测量项目后，不只判断按钮是否成功选中，还读取示波器显示的测量结果，例如：

```text
CH2 峰峰值：1.28 V
CH1 频率：1.00 kHz
```

可能需要：

- 定位测量结果区域；
- OCR 识别数值、单位和通道；
- 判断无效值、超量程和结果未稳定；
- 将结果结构化后返回 Agent；
- 支持一次任务返回多个测量结果。

如果导师期望 Agent 最终真正“完成测量并回答用户”，这一部分应当是测量点击之后的优先工作。

### 2.3 执行反馈、失败重试和任务取消

当前视觉系统已有点击后状态确认的基础逻辑，后续可以完善为完整执行状态机：

```text
等待执行
→ 定位目标
→ 执行点击
→ 检查结果
→ 成功 / 重试 / 失败 / 取消
```

计划能力包括：

- 单步超时；
- 目标未识别时重新检测；
- 点击后状态不正确时重试；
- 记录失败步骤和失败原因；
- 用户中途取消任务；
- 失败后从当前步骤继续，而不是重做全部任务。

### 2.4 获取真实界面状态

当前 Agent 主要根据预设流程生成步骤，并不知道示波器当前处于哪个界面。

后续可以接入视觉状态，使 Agent 能判断：

```text
当前选中哪个通道
Measure 是否已经打开
当前是 Vertical、Horizontal 还是 Other
某个测量项目是否已经启用
是否存在弹窗或异常页面
```

这样可以：

- 跳过已经完成的步骤；
- 避免重复点击当前已选中的组件；
- 从非标准初始界面恢复；
- 根据真实界面重新规划剩余操作。

### 2.5 多轮测量和组合任务

在单个测量任务基础上，支持：

```text
先测量 CH1 的峰峰值，再测量 CH2 的频率
测量 CH3 的最大值、最小值和峰峰值
依次测量四个通道的频率
```

Agent 需要：

- 优化重复的通道和菜单操作；
- 管理多个测量项目；
- 顺序返回多个结果；
- 在部分步骤失败时保留已完成结果。

### 2.6 示波器参数设置

测量功能稳定后，可以扩展到示波器参数配置，例如：

```text
设置通道开关
设置垂直档位
设置垂直偏移
设置水平时基
设置触发源
设置触发电平
设置触发方式
设置采样和采集模式
```

这部分可能涉及：

- 点击；
- 下拉框；
- 数字键盘输入；
- 旋钮或滑动；
- OCR 确认设置值。

其复杂度高于当前测量菜单点击，不建议与第一阶段同时展开。

### 2.7 波形相关操作

候选能力包括：

```text
获取波形截图
定位波形区域
检测波形是否存在
进行简单波形质量判断
保存波形或截图
调用现有波形检测功能
```

需要确认项目目标是“操作示波器”，还是还要求 Agent 对波形进行分析和解释。

### 2.8 系统和辅助功能

原需求中还出现过以下候选能力：

```text
亮度调节
触摸屏检测
设备自检
保存和调用配置
关机
重启
```

这些功能与测量主流程关系较弱，建议只在导师明确要求时纳入。

### 2.9 多型号和通用化

当前工作针对真机上的特定 Rigol 型号和固定机位。

如果最终要求支持多个型号，还需要：

- 不同型号的界面数据；
- 型号识别；
- 分型号的组件映射和工作流；
- 不同页面布局的视觉模型或适配层；
- 不同型号之间的能力差异管理。

这会显著扩大数据采集、标注、训练和测试工作量，不建议默认纳入第一版。

## 3. 建议的开发阶段

### 第一阶段：测量点击 Demo

```text
自然语言任务理解
→ 五种测量项目规划
→ JSON 生成
→ 视觉定位
→ 机械臂点击
→ 点击状态确认
```

交付结果：可以稳定执行若干固定的测量点击任务。

### 第二阶段：完整测量闭环

```text
扩充测量项目
→ OCR 读取测量结果
→ 将数值和单位返回用户
→ 多测量组合任务
```

交付结果：用户提出测量问题后，Agent 能实际操作并返回测量结果。

### 第三阶段：鲁棒执行

```text
真实界面状态识别
→ 跳过重复步骤
→ 失败重试
→ 任务取消
→ 异常恢复
```

交付结果：不再严格依赖固定初始界面，任务失败时能够给出明确原因或恢复。

### 第四阶段：示波器通用操作

根据导师确认的范围，选择性增加：

```text
垂直和水平参数设置
触发设置
采集设置
波形保存与分析
系统和辅助功能
```

### 第五阶段：多型号适配（可选）

只有在项目明确要求通用化时，再支持多个示波器型号和不同界面布局。

## 4. 建议的最终目标定义

目前可以将项目最终目标分成三个层级，请导师确认希望达到哪一级。

### 目标 A：自然语言任务配置器

```text
自然语言
→ 生成合法任务 JSON
```

Agent 不负责真实执行和结果读取。

### 目标 B：测量操作 Agent

```text
自然语言
→ 规划测量步骤
→ 控制视觉和机械臂执行
→ 检查操作是否成功
→ 读取并返回测量结果
```

这是当前最推荐的最终目标，范围明确，也能形成完整闭环。

### 目标 C：通用示波器智能操作 Agent

```text
测量
+ 参数设置
+ 触发和采集配置
+ 波形分析
+ 系统功能
+ 多型号适配
+ 自动失败恢复
```

该目标工作量明显更大，需要扩大视觉数据、操作模板、状态管理和测试范围。

## 5. 建议与导师确认的问题

1. 第一阶段只做测量点击配置，是否符合预期？
2. 最终是否必须读取测量数值并回答用户？
3. 最终目标选择 A、B 还是 C？
4. 是否要求支持垂直档位、水平时基和触发参数设置？
5. 是否要求进行波形识别或波形分析？
6. 是否包含亮度、自检、触摸屏检测、关机和重启等辅助功能？
7. 是否要求支持多个 Rigol 型号？
8. 是否要求 Agent 在任意初始界面下自动恢复和执行？
9. 最终演示入口是独立 Agent，还是集成到 Qt 客户端？
10. 项目验收更关注自然语言规划、机械臂操作闭环，还是测量结果准确性？

## 6. 当前建议

建议将最终目标暂定为“目标 B：测量操作 Agent”：

```text
第一步：完成测量菜单点击配置
第二步：完成视觉和机械臂执行闭环
第三步：读取并返回测量结果
第四步：增加状态识别、重试和多任务
```

参数设置、波形分析、系统功能和多型号适配作为可选扩展，由导师确认后再决定是否纳入。
